# ProjectTracker – Frontend

Angular frontend for the SaaS Project Tracker (Jira-style project and issue tracking).
Backend: [`saas-project-tracker-backend`](https://github.com/abiroh-p/saas-project-tracker-backend) (Django REST).

- Angular 22, standalone components, signals, zoneless change detection, OnPush everywhere
- SCSS with design tokens (CSS custom properties). No UI framework: components follow the approved UI/UX showcase
- Reactive forms, functional guards and interceptors, Vitest for unit tests

## Requirements

- Node.js **22.22.3+** or **24.15+** (required by Angular CLI 22)
- The backend running on `http://localhost:8000`

## Getting started

```bash
npm install
npm start            # http://localhost:4200 – proxies /api to http://localhost:8000
npm test             # unit tests (Vitest)
npm run build        # production build in dist/
```

`ng serve` proxies `/api` to the Django backend (`proxy.conf.json`), so the browser only talks to one
origin and no CORS setup is needed. In production, serve the built app and the API from the same
origin (reverse proxy) or change `apiUrl` in `src/environments/environment.ts`.

While in development, **http://localhost:4200/design-system** shows the design tokens and every shared
component. Check it whenever you change a token or a UI primitive.

## Project structure

```
src/
  environments/          apiUrl
  styles/                _tokens.scss (design tokens), _base.scss (reset, typography, focus)
  app/
    core/                singletons, no UI
      api/models/        TypeScript types that mirror the API (User, Page<T>, ApiError, ...)
      auth/              AuthService, SessionStore, token storage + refresh, guards, interceptor
      http/              error normalisation (ApiError) and its interceptor
      forms/             validation messages, server-error mapping, validators
      config/            API_BASE_URL injection token
    shared/ui/           reusable presentational components (button, text-field, checkbox, alert, icon, logo)
    features/            one folder per product area, lazy loaded (auth, dashboard, projects, issues, profile)
```

Rules of thumb:

- `core` never imports from `features`; `features` may import from `core` and `shared`.
- Styling uses tokens only (`var(--color-primary-600)`, `var(--space-4)`), never raw hex values.
- Components are standalone, `OnPush`, use `input()` / `output()` / signals and the new control flow.
- Anything that talks to the API lives in a service under the feature (or `core`), never in a component.

## Authentication flow

0. Pages: `/sign-in` (email **or** username + password, "remember me") and `/sign-up` (full name, email,
   password, confirmation). The username is generated by the backend from the email. Sign-up does not
   sign the user in; it redirects to `/sign-in?registered=1`. `/dashboard` is a placeholder for now.
1. `AuthService.login()` stores the JWT pair (`localStorage` with "remember me", otherwise
   `sessionStorage`) and puts the user into `SessionStore`.
2. `authInterceptor` adds `Authorization: Bearer <access>` to API calls. On a `401` it refreshes the
   token once (shared between concurrent requests) and retries. If the refresh fails the session is
   cleared and the user is sent to `/sign-in?returnUrl=…`.
3. `errorInterceptor` converts every failure to `ApiError` (`{ status, code, detail, errors? }`).
   Forms use `applyServerErrors(form, error)` to show field errors next to the inputs.
4. `provideAppInitializer` calls `AuthService.restoreSession()` so a valid stored session is restored
   before the first navigation. `authGuard` / `guestGuard` protect routes.
5. `AuthService.logout()` blacklists the refresh token (best effort) and always clears local state.

Tokens are kept in web storage because the API returns them in the response body. Mitigations are
the short access-token lifetime, token blacklisting on logout, and no `innerHTML`/untrusted HTML
anywhere. Moving to httpOnly cookies would require backend changes.

## API conventions the frontend relies on

- Base path `/api/v1`; JWT bearer auth.
- Errors: `{ detail, code }`, validation errors add `errors: { field: string[] }`.
- Lists: `{ count, next, previous, results }` with `page` and `page_size`.

## Testing

`npm test` runs the unit tests. The interceptor, token refresh, auth service, guards, error
normalisation and shared components all have tests. Add tests alongside new code
(`*.spec.ts` next to the file).
